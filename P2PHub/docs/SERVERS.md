# Серверы в ОСГОворим

> Незнакомые слова — в [GLOSSARY.md](GLOSSARY.md).

В проекте не один «сервер», а **до трёх маленьких ролей**. Каждую можно закрыть
бесплатно или вообще чужим публичным сервисом.

## Роль 1. Хостинг сайта (где «лежит» PWA)

Хранилище для `index.html`, `style.css` и т.д. Нужен **HTTPS** (иначе PWA и
уведомления не работают).

| Сервис | Чем хорош |
|---|---|
| **GitHub Pages** ⭐ | Уже дружит с нашим репо. Используем сейчас. |
| Netlify | Перетащил папку — готово. |
| Cloudflare Pages | Быстрый, щедрый бесплатный тариф. |

## Роль 2. Signaling-сервер (знакомит пиров для WebRTC)

- **Старт:** публичный **PeerJS** или публичные WebTorrent-трекеры — ничего не поднимаем.
- **Свой (позже):** крошечный Node.js-скрипт на бесплатном тарифе **Render /
  Railway / Fly.io**, либо «серверless» **Cloudflare Workers / Deno Deploy**.

## Роль 3. Push-relay (будит телефон уведомлением)

- **Готовый сервис:** **OneSignal** (free) — сам разбирается с FCM и APNs.
- **Свой:** библиотека `web-push` (Node.js) на том же Render/Railway/Pi.

## Что используем для старта

| Роль | Старт | Цена |
|---|---|---|
| Хостинг сайта | **GitHub Pages** | бесплатно |
| Signaling | публичный PeerJS / трекеры | бесплатно |
| Push | пока нет (только при открытом приложении) | бесплатно |

То есть на старте **свой сервер не нужен вообще**.

## Своё железо: Raspberry Pi (+ кластер на k3s) — Этап 5

Когда захотим полную независимость от чужих сервисов:

- **Одна Raspberry Pi** спокойно держит signaling + push-relay (Роли 2 и 3).
- **Кластер из нескольких Pi** даёт отказоустойчивость: одна упала — сервис
  работает на других.
- **Оркестрация — k3s** (лёгкий Kubernetes под слабое железо Pi). Он
  распределяет наши сервисы по узлам и перезапускает упавшие.
- Настройку кластера и k3s можно сделать пошагово, когда дойдём до этого этапа.

> Важно: даже со своим сервером данные (сообщения, файлы) остаются P2P —
> сервер только знакомит пиров и шлёт «толчки» уведомлений.

## Заметка про бесплатные тарифы

На free-тарифах Render/Railway сервер «засыпает» без активности, и первый ответ
идёт с задержкой пару секунд. Для signaling это терпимо; для продакшена позже
улучшим (платный тариф или свой Pi).
